## B. Truncation never lands inside a code fence (`handoff/trim.py:86`, `handoff/extract.py:141`)

**Defect (measured):** an assistant turn `intro\n```python\n` + 900 lines +
```` ``` ```` truncates to 4 056 chars containing exactly ONE ```` ``` ```` and the
cut lands mid-line. Everything after it in the brief renders as code.

**Fix:** one helper in `handoff/extract.py` (trim imports extract, not the
other way round), used by both truncation sites:

```python
def cut_at_line(text: str, limit: int) -> str:
    """Truncate to ≤ limit chars at the last newline before the limit (a
    mid-line cut is unreadable), then close a fence the cut left open — an
    odd number of ``` turns the rest of the brief into code."""
    head = text[:limit]
    nl = head.rfind("\n")
    if nl > 0:
        head = head[:nl]
    head = head.rstrip()
    if head.count("```") % 2:
        head += "\n```"
    return head
```

- `_classify_assistant`: `joined[:ASSISTANT_TURN_MAX_CHARS].rstrip()` →
  `cut_at_line(joined, ASSISTANT_TURN_MAX_CHARS)`. `elided` is computed as
  `len(joined) - len(head)` AFTER the cut (the marker must report what was
  actually removed).
- `extract.elide_pasted_output`: `text[:preserve_chars].rstrip()` →
  `cut_at_line(text, preserve_chars)`. Keep the `elided <= 0` early return.

**Acceptance:** `test_assistant_truncation_closes_open_fence`,
`test_assistant_truncation_cuts_at_newline`,
`test_pasted_elision_cuts_at_newline`. The exact expected lengths are in the
test — derive nothing.

(`/Users/<name>/…` → username inside every memory doc); `project` is

**Fix:**

```python
def _home_relative(path: str) -> str:
    """`/Users/me/x` → `~/x`. The archive is a memory doc that outlives the
    machine; a username in it is both PII and wrong after a rename."""
    home = str(Path.home())

```

and in `handoff/recall.py`, `project_tag_from_cwd` sanitises the basename:
`re.sub(r"[,\s]+", "-", base)` — `,` is the tag separator on the `memory` CLI

## F. `trim.py` three trimmer defects (`handoff/trim.py:136-156, 315, 332`)

### F1. ≤80-char substantive answers survive `same_turn_drop` / `adjacent_drop`

**Measured** across small/medium/large/huge: 263 assistant texts ≤80 chars are
dropped by those two rules. Gating on "has a code anchor and no narration
phrase" rescues exactly 7, all genuine findings (`` `max-limit=0` means 0bps,
not unlimited``, ``Bug — `delete` removed ALL matches``, …) and keeps dropping
the 256 narration lines (`Now commit and push.`). A plain NARRATION_RE-prefix
gate rescued 91, mostly narration — rejected.

```python
# A short turn next to a tool call is usually narration ("Now push."), but a
# short turn carrying a code anchor and no narration verb is a finding
# ("`delete` removed ALL matches"). Measured 2026-09-21: 7 of 263 rescued.
SHORT_SIGNAL_RE = re.compile(r"`|\*\*")
SHORT_NARRATION_RE = re.compile(
    r"\b(let me|let's|i'?ll|now (?:i|let|update|find|save|the|commit|push|amend|make|activate)|going to)\b",
    re.IGNORECASE,
)

def _short_signal(text: str) -> bool:
    return bool(SHORT_SIGNAL_RE.search(text)) and not SHORT_NARRATION_RE.search(text)
```

`same_turn_drop = len(text_joined) <= 80 and tool_markers and not _short_signal(text_joined)`;
same `and not _short_signal(text_joined)` on `adjacent_drop`.

### F2. `nxt` skips `DROP_TOP_TYPES` entries (`build_convo`, line 315)

**Measured:** `[assistant "Fix is in db.py:12 — the WHERE clause.", user tool_result]`
→ `[]` (dropped as adjacent-to-tool) but insert a `file-history-snapshot` between
them → the text is kept. Same conversation, different brief.

Fix: `nxt` is the next entry whose `type` is NOT in `DROP_TOP_TYPES`. Precompute
once (O(n)), don't scan forward per entry:

```python
nxt_idx = [None] * len(entries)
following = None
for i in range(len(entries) - 1, -1, -1):
    nxt_idx[i] = following
    if entries[i].get("type") not in DROP_TOP_TYPES:
        following = entries[i]
```

then `nxt = nxt_idx[i]`.

# handoff/extract.py

## G. Command files: `$ARGUMENTS` handling (`commands/done.md`, `archive.md`, `holds.md`, `tasks.md`)

**Defect:** `done.md`/`archive.md` build `SID="${ARG// /}"` — two accidental
sids concatenate into one 72-char token (measured: dbcli then says
`no brief at …<72 chars>.md`, safe but misleading). `holds.md`/`tasks.md`
expand `$ARGUMENTS` unquoted with no `set -f` → a `*` globs.

**Fix:**

- `done.md` and `archive.md`:

  ```bash
  set -f; set -- $ARGUMENTS; set +f
  FLAG=""; SID=""
  for a in "$@"; do
    case "$a" in
      --reopen) FLAG="--reopen";;      # archive.md: --unarchive
      -*) echo "HANDDONE_ERROR unknown flag $a"; exit 1;;
      *) [ -n "$SID" ] && { echo "HANDDONE_ERROR one session id at a time (got '$SID' and '$a')"; exit 1; }; SID="$a";;
    esac
  done
  [ -z "$SID" ] && { echo "HANDDONE_ERROR usage: /hand:done <session-id> [--reopen]"; exit 1; }
  cd ~/repos/handoff && PYTHONPATH=. python3 -m handoff.dbcli done "$SID" $FLAG
  ```

  Same shape for `archive.md` with `HANDARCH_ERROR` / `--unarchive`.
- `holds.md`, `tasks.md`: add `set -f` as the first line of the bash block
  (mirrors `on.md`, `review.md`).

**Acceptance:** `tests/test_commands_args.py` (also already red): extracts the
bash block of each `commands/*.md`, substitutes `$ARGUMENTS` textually (that is
what CC does), runs it with a `python3` shim on PATH that prints its argv, and
pins: two sids → `*_ERROR one session id`; `*` → the shim receives a literal
`*`; `set -f` present in every block that expands `$ARGUMENTS` unquoted.
